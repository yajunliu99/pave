# 拍摄点 mapping 与车道证据视图

本模块从冻结的 V6 视觉推断结果构建地理观测图，可叠加独立的下游 GSV 复核结果。推断不读取人工评估答案；历史判断与新增判断分别保留。

## 使用

```powershell
python scripts/pipeline/run_control_pipeline.py --config configs/control_sites/node_351.json --output experiments/control_generic_351_v2 --atlas-base experiments/geospatial_evidence_351_20260915_billing --cache-only
python dashboard/build_standalone_dashboard.py --atlas experiments/control_generic_351_v2/atlas
```

第二条命令把 atlas 目录打包为单文件 dashboard/dashboard.html（脚本、数据和图片全部内嵌），直接双击打开，不需要本地服务。点选候选区域后查看源图与模型引用；选择观测可切换引用局部、全图和地图视线候选。

## 数据与几何

- 地理锚为 buf120 的六位小数 bbox 请求拟合、Web Mercator、实际解码尺寸。零 padding 是依据请求代码重建的参数。
- buf40 的实际视野与 buf80 几乎相同。使用 SIFT/稳健仿射与留出块校验恢复 buf40→buf120，对应宽约159.4m，而非请求宽约80.3m。该修正不能推广成所有静态图固定倍率。
- 经纬度/局部米制/像素坐标可以往返，但绝对精度仍需独立地理控制点验证。
- GSV 使用返回全景的实际坐标。全景投影角减去缓存 yaw 才是指南针方向；例如 EB 1° 的投影角对应 90° 东向。
- 请求点与全景位置距离保留为 snap distance，不当作定位误差。
- GSV 框只转换为带角度范围的视线；没有标定相机高度、地面对应或对象高度时，不生成精确地面位置。
- 来源按原始卫星图/全景分组，避免多裁剪重复计数；不同来源组也不自动意味着统计独立。
- LaneGraph 保存候选车道段、模型观测、关联假设及版本沿革。增删、拆分、合并接口要求存在的观测 ID；本轮没有自动改写候选边界。

## 当前范围

已实现 P0 基线冻结、P1 坐标与实际拍摄点落图，以及最小观测库、空间候选和可点击关联图。9/15 新增四个出口各约25/50/100 m的向外、回望视图，共24幅，并完成四个出口的独立 VLM 复核。

用户开启 Billing 后重新查询，12个出口位置全部成功，返回坐标位于名义同向侧。新增24幅官方 Static Street View 影像（640×640），保留24幅既有对向侧辅助视图；出口证据共48幅、24个全景来源。EB/SB 新位置影像为2025-11，NB/WB 为2024-06，后者仅为历史依据。界面与模型提示逐张区分所在侧和日期，名义坐标不等于独立标定的车道位置。

`regions` / `region_registry` 保存37个区域及其历史ID；`lanes` / `segments` 只保存模型支持的机动车候选。其他交通设施、已否定区域、待定区域分别保存，具体计数见当次报告。历史ID中的 `lane/` 不是类别依据，应读取 `graph_role` 和 `movement_endpoint_eligible`。否定区域默认不显示，只在“已否定区域（审计）”图层显示灰色叉线，不计入车道数，也不作为 movement 端点。其机动车用途显示“不适用”，high 表示模型对非道路分类的自报置信。

出口复核从原始候选和图片重新推断，不向模型提供前一轮分类作为答案。此前对向侧复核保存在 downstream_audit_351_20260915，加入同向侧影像的复核保存在 downstream_audit_351_20260915_billing。当前 movement 仍为冻结基线，未根据此次出口判断重跑。

P2 精确地面配准、绝对车道级定位、独立关联验证、自动候选生成和联合 movement 推断尚未完成。已有地面单应性/高度接口只在明确标定输入下启用。不能把当前视场或模型关联当作已验证对应。

当前输出、指标及状态见 experiments/control_generic_351_v2/atlas/report.md 和 validation.json。出口复核原始输入、响应和缓存见 experiments/downstream_audit_351_20260915_billing。

## 信号灯与标志

当前控制设施流程已通用化，详见 [通用采样与运行说明](traffic_control_pipeline.md)。入口不再硬编码路口中心、四个方向和固定7m横向偏移；新增不同位置补图闭环。以下为首版固定采样的历史记录。

控制设施使用独立取景流程：沿每个进路在相对路口中心 -25/-10/+8 m 请求拍摄点（不是距信号灯的距离），保留实际全景坐标和日期；抬头12°、100°视场提供上下文。YOLO26n 提供交通灯和 stop sign 候选，VLM 从不同站位选择目标，再以原生图像框的射线计算朝向、仰角和15—55°视场，取得同全景特写。没有使用生成式增强补画文字。

本轮新增12幅上下文和12幅特写，来自9个全景；其中6个位置是此前图集中没有的。所有控制视图日期均在2025-10—11。VLM生成35项按方向分组的设施假设、48条图像引用；不同方向可能重复看到同一设施，不能将35解释为物理设施总数。NB/SB 的 LEFT ON GREEN ARROW ONLY 和禁止掉头图形、EB 的 DO NOT STOP IN BOX 已有可读引用；部分灯头暗孔箭头和小标志仍不可读。

`controls` 保存设施假设，`control_bindings` 保存适用范围与候选关联，`traffic_control` 观测保留原生框与来源组。所有具体车道绑定在本轮仍未确定，不把信号牌读取直接变成车道用途硬约束。静态灯色不推断配时、相位顺序或永久通行许可。控制设施只有视线方向，没有未经标定的地面点。

页面新增“信号灯与标志”选择器；点击设施或来源按钮可查看特写、识别内容、适用范围和不确定项。完整输入、YOLO输出、VLM提示与响应保存在 experiments/control_audit_351_20260915。
